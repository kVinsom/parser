# Випуск 0.1.0-rc1

Поточна політика: **Autobuy — Soon**, функція вимкнена для всіх користувачів.
[Зміни від 13.10.2026](AUTOBUY_SOON_2026-10-13.md). Попередні перевірки автобаю
нижче описують збережену реалізацію, а не ввімкнену функцію релізу.

Остання повна автоматична перевірка: [13.10.2026](RELEASE_AUDIT_2026-10-13.md).
Після виправлень пройдено 1 962 тести та 86 підперевірок. Живий автобай
залишається поза підтвердженою готовністю; подробиці — у звіті.

Серверний комплект Linux/VPS додано 11.10.2026:
[інструкція, перенесення й результати перевірки](../deploy/README.md).
Зібрано та перевірено на Linux-контейнерах; цільовий VPS ще не підключено.

Первинний шлях запуску цього кандидата: Windows, Python 3.12+, PowerShell
та Docker Desktop із Linux-контейнерами. Ціни — EUR/GBP, регіони — GB/FR/IT/DE.
Currency-adapter відкладено за рішенням власника. Autobuy не ввімкнений у
чистому встановленні; жива автоматична оплата не перевірена й не входить до заявленої
готовності. Ручне оформлення підписки не вмикає тарифних обмежень пошуку.

## Чисте встановлення

1. Розпакувати архів у постійний каталог. `MANIFEST.json` містить SHA-256
   кожного файла. Не копіювати чужі `.env`, профілі браузера чи бази.
2. Відкрити PowerShell у корені й виконати:

   ```powershell
   .\tools\setup.ps1 -Python python
   ```

   Якщо Python відсутній у PATH, передати повний шлях до Python 3.12 через
   `-Python`. Скрипт створить три окремі середовища, встановить залежності,
   згенерує контракти parser і скопіює лише відсутні `.env.example` у `.env`.
   Worker/notifier використовують середовище Telegram-бота та моделі parser
   із дерева вихідного коду. Окремий запуск notifier не потрібний.
3. У `services/telegram-bot/.env` задати `TELEGRAM_BOT_TOKEN`. Для випуску
   залишити `APP_ENV=production`, `MENU_MODE=menu`, `UPDATE_MODE=polling`.
   Для проксі заповнити `services/access-gateway/bypass/.env`; секрети не
   передаються в архів і не друкуються діагностикою.
4. Для перевірок підняти тестові залежності:

   ```powershell
   docker compose -f services/telegram-bot/compose.yaml up -d --wait
   .\tools\check_release.ps1
   ```

   Перевірка створює окремі випадкові схеми PostgreSQL і тестові ключі Redis.
   Вона не надсилає реальних повідомлень та не викликає покупки. Результати
   записуються в `.release-checks/<час>/`. Невдала перевірка повертає ненульовий
   код. `-SkipIntegration` дає лише часткову перевірку. На Windows потрібний
   доступ до тимчасових каталогів.
5. Запустити живі процеси:

   ```powershell
   .\start.ps1
   .\services\worker\run.ps1 -Mode status
   ```

   Launcher підіймає PostgreSQL/Redis, збирає gateway, чекає контейнерів,
   застосовує міграції й запускає worker та бот. Worker запускає parser.
   Негайне аварійне завершення більше не виглядає успішним стартом. Процес,
   що працює кілька секунд, ще не доводить доступність Telegram/Vinted:
   перевірити журнали та реальний сценарій власним тестовим акаунтом.

Перше призначення адміністратора описане в Telegram README; воно потребує
справжнього `/start`, перевіреного Telegram ID й явного підтвердження.

## Оновлення наявної установки

- Зберегти резервну копію PostgreSQL, `.env`, локальної політики свіжості й
  потрібних профілів до заміни коду. Не виконувати `docker compose down -v`.
- `publication_policy.json` задає спільну для всіх користувачів межу 60 секунд.
  Пакування та перенесення не додають персональних винятків.
- Оновити залежності через `setup.ps1`, виконати повну перевірку, запустити
  `start.ps1`. Він перезапускає процеси, зберігаючи дані й наміри пошуку.
- Контейнери мають `restart: unless-stopped`; для локального worker є
  `services/worker/tools/install_watchdog.ps1`, який відновлює його після входу
  у Windows. Для всіх процесів на Linux використовуй серверний Compose.
  Поточні Compose-файли використовують локальні порти та локальні паролі;
  це конфігурація локального хоста, не публічної бази даних.

## Невизначені сповіщення

Перед зверненням до Telegram квитанція/сповіщення записується як `unknown`.
Успішна відповідь змінює стан на `sent`; явна відмова через ліміт повертає
`pending` із затримкою. Втрата відповіді, скасування або аварія зберігає
`unknown`, щоб не дублювати вже прийняте повідомлення. Аварія між записом
стану й мережевим викликом може також залишити недоставлене `unknown`.
Такі записи в `bot_notifications` потребують ручної звірки; автоматично
повертати всі `unknown` до черги не можна. Бізнес-операція підписки/заявки
залишається збереженою незалежно від стану її повідомлення.

## Очищення та пакування

`tools/clean.ps1` видаляє тільки `__pycache__`, `.pytest_cache`, `.ruff_cache`
після перевірки шляхів. Не чіпає середовища, бази, `.env`, `.artifacts`,
браузерні профілі, налаштування редактора або звіти аудиту. Старі артефакти
досліджень збережені: на частину з них посилається історія діагностики.

`tools/build_release.py` пакує вихідний код, контракти, конфігураційні шаблони,
тести й документацію за явними правилами. У пакеті немає локальних залежностей,
секретних `.env`, кешів, сирих знімків або профілів браузера. Персональна
політика віку в архіві замінена спільним правилом 60 секунд; локальна політика не змінюється. Пакувальник
відмовляється перезаписувати вже створений архів.

## Перевірка зовнішніх систем

Автоматичні тести перевіряють контракти й обробку збоїв на імітованих відповідях.
Готовність gateway означає доступність його процесу; вона не доводить, що
Vinted приймає поточний проксі. Перед відкриттям доступу перевірити власним
тестовим акаунтом `/start`, створення фільтра, початковий прохід, появу нового
лота, Stop і перезапуск. Результати локального аудиту:
[RELEASE_AUDIT_2026-09-29.md](RELEASE_AUDIT_2026-09-29.md).
