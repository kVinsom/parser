# Обробка Telegram та адміністрування

[README сервісу](../README.md) · [Діалоги](DIALOGS.md) · [Етап 2: підписки](SUBSCRIPTIONS.md) · [Адмінправа](ADMINS.md)

Стек: aiogram 3, aiohttp webhook, FSM/RedisStorage, SQLAlchemy Async/PostgreSQL.

- Реєструє користувача при /start; зберігає внутрішній Telegram user ID у 64-бітному полі та поточний username для пошуку отримувача в адмінпанелі. Роль і пошуки прив'язані до акаунта за ID.
- Показує меню «Фільтр», «Почати пошук», «Завершити пошук» та окремі картки предметів. «Додати предмет» запускає послідовний діалог англійською з «Додати ще»/«Пропустити». Збереження й відновлення перевіряють власника та версію в транзакції; повторні дії не створюють дубль. Тарифного ліміту й меню оплати немає.
- Підтверджує натискання кнопки швидко; мережевий пошук сайтів виконується окремо. Перша інтеграція — Vinted; дані пошуку містять source_id для подальшого підключення джерел.
- Обробляє надання/зняття глобальних адмінправ за @username з підтвердженням і журналом операцій. Зміна днів та оплата належать етапу 2.
- Перевіряє поточну роль адміністратора за Telegram ID при кожній привілейованій дії та підтвердженні. Старий діалог не зберігає права після їх зняття.
- Для кожної частини застосовує can_monitor: власний неархівований пошук, вибране ввімкнене джерело та придатні фільтри. Worker і notifier додатково перевіряють активність та покоління. Підписка й кількість предметів не перевіряються. Повний Stop зупиняє всі частини зі збереженням параметрів. Майбутнє розширення — у [ROADMAP.md](../../../docs/ROADMAP.md).
- Отримані оновлення webhook приймаються надійно: до підтвердження Telegram вони збережені або передані у надійну чергу. Повторні update_id не повторюють мутації.
- Використовує secret token webhook; приватні API сервісів не відкриті в інтернет.

FSM дає змогу вести діалог по кроках, RedisStorage зберігає його стан. [aiogram FSM](https://docs.aiogram.dev/en/latest/dispatcher/finite_state_machine/index.html), [сховища aiogram](https://docs.aiogram.dev/en/latest/dispatcher/finite_state_machine/storages.html).

## Пошук користувача за username

Сценарій керування адмінправами (на етапі 2 використовується також для підписок): бот питає «Введіть @username користувача», приймає ввід з `@` або без нього, прибирає зовнішні пробіли й порівнює нормалізовані значення без урахування регістру. Ім'я профілю не замінює username. На екрані підтвердження показуються знайдений @username, ім'я та результат операції; числовий ID вводити не потрібно.

Отримувач має спочатку запустити /start. Бот оновлює username за власними повідомленнями/натисканнями цього користувача, включно з видаленням ніка; пересланий текст чи введений адміністратором рядок не оновлюють профіль отримувача. Якщо нік відсутній, для керування через цей діалог отримувач має встановити його в Telegram і написати боту. Невідомий username не створює користувача або відкладену видачу прав.

Bot API передає ID користувача й необов'язковий username. Метод getChat приймає @username для супергруп/каналів; пошук довільної приватної особи за ніком цим методом не передбачений. Тому в проєкті username спочатку зіставляється з уже відомим акаунтом у базі. [Telegram User](https://core.telegram.org/bots/api#user), [getChat](https://core.telegram.org/bots/api#getchat).

Перед показом отримувача та повторно перед застосуванням зміни бот перевіряє актуальний username через getChat за збереженим числовим ID приватного чату. У разі невідповідності, неоднозначності або помилки перевірки зміна не застосовується; бот пропонує оновити дані та повторити пошук. Після вибору отримувача операція фіксує його внутрішній ID: повторне підтвердження не може перенаправити її на інший акаунт. [Поточні дані чату](https://core.telegram.org/bots/api#getchat), [ChatFullInfo](https://core.telegram.org/bots/api#chatfullinfo).

Зміна або видалення username не переносить і не скасовує роль чи пошуки. Старий нік перестає бути чинним ключем пошуку після перевірки/оновлення; історичні ніки залишаються тільки в журналі. Обробка оновлень профілю враховує їхній порядок і версію, щоб стара подія не перезаписала новіші підтверджені дані.
