## Поточна реалізація — 2026-09-27

`vpars_notifier/service.py` доставляє підтверджені збіги з PostgreSQL
`vpars_monitor.deliveries`. Запускається як окремий компонент фонового
процесу через `../worker/run.ps1 -Mode start`, поза процесом Telegram-діалогів.
Повторні доставки, Stop, вибір маркетплейсів, пріоритет меню, помилки фото,
429 та невизначені результати перевіряються перед кожною спробою.
Форматування й спільний Redis-бюджет використовуються з `telegram-bot`.
UAH-конвертер не підключений: показується оригінальна ціна із символом валюти
після суми (наприклад, `144.50 €` або `45.00 £`). Для валют без відповідного
символу в таблиці форматування залишається код валюти.
Картка англійською має шість рядків: Market, Brand, Size, Condition, Price,
Reviews. Текст — жирним курсивом. Ім’я продавця не показується. Оцінка — зірками,
кількість відгуків — у дужках; дробова оцінка додатково показується числом /5.
Дані зберігаються разом із галереєю й повторно використовуються
після рестарту. Старі галереї в черзі без продавця уточнюються до початку
надсилання; відсутня інформація позначається N/A і не блокує лот.
Кнопки Open (посилання) та Buy (бездіяльна заглушка) стоять в одному рядку.
Фото/галерея, картка й кнопки надсилаються одним `sendRichMessage` і мають
один message_id. Підтверджена доставка не повторюється після рестарту;
429 відкладає весь лот. Для старої часткової черги враховано вже надіслані фото.
На один лот надсилаються максимум 10 перших унікальних фотографій у порядку
джерела. Ліміт спільний для всіх маркетплейсів і застосовується також до
раніше збережених галерей та повторів. При відхиленні фото виконується спроба
єдиної картки з обкладинкою, потім — без фото з короткою приміткою.
Решта фотографій доступна за посиланням на оголошення.
Запуск, перевірки та обмеження описані в [worker](../worker/README.md).
Нижче збережений план подальшої архітектури доставки.

## Відповідальність

Доставка карток лотів у Telegram, перерахунок ціни через адаптер валют, перевірка актуальності завдань, технічні ліміти API та облік результату.

## Як працює

1. Отримує завдання з outbox/черги.
2. Перевіряє власника, ввімкнене джерело й хоча б один відповідний активний пошук із чинними поколінням і версією фільтрів, без тарифних перевірок.
3. Для лота отримує від currency-adapter еквівалент UAH та готує фото з ціною у двох валютах, назвою сайту, регіоном, доступними атрибутами й посиланням на джерело.
4. Після конвертації й очікування ліміту повторно перевіряє актуальність пошуку та Stop перед початком відправлення.
5. Надсилає повідомлення з урахуванням лімітів Telegram і зберігає message_id та статус доставки.
6. Обробляє тимчасові помилки, невизначений результат відправлення та блокування бота користувачем.

## Стек і залежності

Python/asyncio, aiogram Bot API client, Taskiq/Redis Streams, PostgreSQL. Залежить від currency-adapter, Telegram Bot API та актуальних даних пошуків і доставки.

Повний Stop припиняє всі нові лоти; архівування/редагування скасовує повідомлення, які не мають жодного чинного активного збігу. Уже прийнятий Telegram запит має обмеження скасування. Діалоги обробляє telegram-bot. Підписки, квоти й службові нагадування з'являться на [етапі 2](../../docs/ROADMAP.md).

## Архітектурні патерни

Outbox Relay/Consumer передає довговічні наміри доставки виконавцям. Delivery State Machine, ідемпотентність і спільний Rate Limiter керують станами, повторами й частотою повідомлень. Message Builder відокремлює форматування від надсилання та fallback. Деталі — в [архітектурі notifier](docs/ARCHITECTURE.md).
