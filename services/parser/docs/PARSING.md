# Робота парсера: каталог → нормалізовані лоти

[README](../README.md) · [Промпт реалізації](../IMPLEMENTATION_PROMPT.md) · [Архітектура](ARCHITECTURE.md) · [Етапи проєкту](../../../docs/ROADMAP.md)

Статус на 2026-09-22: сервіс реалізований і перевірений локально та окремими живими запитами через gateway. Нижче збережено правила розбору й межі відповідальності. Точні HTTP-моделі, назви полів, коди помилок і команди — у [README](../README.md); фактичні перевірки — у [VALIDATION.md](VALIDATION.md).

## Межа відповідальності

Parser отримує один запит каталогу від worker, завантажує одну сторінку через gateway, розбирає її й повертає нормалізовані лоти. Він не запускає постійний моніторинг і не визначає, кому надіслати оголошення.

- Gateway виконує мережевий доступ, роботу браузера, проксі й антибот-перевірки.
- Parser перевіряє можливості фільтрів, будує запит, розбирає сторінку, нормалізує поля й описує повноту результату.
- Worker задає розклад і межу перегляду, обходить сторінки, остаточно перевіряє всі фільтри та відсіює вже доставлені користувачу лоти.
- Notifier формує повідомлення й отримує гривневий еквівалент через валютний адаптер. Parser повертає вихідну валюту та ціну.
- Telegram-бот веде діалог і зберігає пошук. Parser не отримує Telegram-токен, username, підписку чи історію користувача.

Поточний етап не має підписок і тарифних квот предметів. Їх не потрібно додавати в parser навіть як вимкнені перевірки.

## Що вже надає сервіс доступу

Джерело правди — наявні [access.proto](../../access-gateway/bypass/proto/vinted_rpc/access.proto), [grpc_server.py](../../access-gateway/bypass/grpc_server.py), [vinted.py](../../access-gateway/bypass/vinted.py), [реєстр регіонів](../../access-gateway/bypass/vinted_regions.py) та [GRPC.md](../../access-gateway/bypass/GRPC.md). Перед реалізацією перечитати їх: код може змінитися після цієї специфікації.

| Частина | Перевірений стан |
|---|---|
| Сервіс | gRPC vpars.access.v1.VintedAccess; ListRegions і FetchCatalog |
| Адреса | Через налаштування: локально 127.0.0.1:50051, у мережі наявного Compose — gateway:50051 |
| Регіони | UK (GB — синонім), FR, IT, DE; PL вимкнено й відхиляється до браузера |
| Запит | region, search_text, page, timeout_seconds, include_html, load_media, measure_timing |
| Межі | search_text до 500 байтів UTF-8; page ≥ 1; timeout_seconds 1–300 |
| Відповідь | outcome, метадані та html_utf8; HTML повертається тільки за PAGE_LOADED і include_html=true |
| Паралельність | Типово один браузерний виклик; конфігурація gateway допускає 1–4 |
| Транспорт | Вхід gateway до 64 КіБ, відповідь до 32 МіБ; використовується gRPC gzip |

ListRegions визначає доступні регіони; історичний список із PL у загальних документах не є дозволом знову ввімкнути Польщу. Parser реалізує лише доступні регіони та явно відхиляє непідтримуваний.

У контракту зараз немає полів для стану, розміру, бренду, кольору, категорії, цінових меж, сортування, довільного URL або JSON endpoint. Parser не підставляє їх у search_text і не обходить gateway прямими запитами до Vinted. Прогалини інтеграції описуються явно; потрібне розширення gateway має бути окремою сумісною зміною.

## Послідовність одного виклику

1. Перевірити source_id, доступність регіону, номер сторінки, типи й узгодженість фільтрів. Невідоме джерело/регіон відхилити до мережевого виклику.
2. Вибрати SourceAdapter із реєстру. Для першої реалізації існує тільки VintedAdapter.
3. Визначити, які фільтри можна застосувати в запиті джерела, які перевірятиме worker за отриманими полями, а які поки не підтримуються.
4. Побудувати один регіональний запит FetchCatalog. Для розбору обов'язково include_html=true; типово load_media=false, оскільки потрібні URL фото, а не завантажені зображення.
5. Дочекатися результату в межах спільного бюджету часу. Спочатку перевірити gRPC-статус, outcome, регіон і фінальний URL, потім декодувати HTML.
6. Розібрати підтверджені картки каталогу. Якщо у фактичному HTML є придатні структуровані дані, можна використати їх; їхні назви, шляхи та схеми встановлюються за зразками, а не припускаються.
7. Нормалізувати поля, перевірити базові дані лота, об'єднати повторні посилання на один лот у межах сторінки.
8. Повернути лоти, дані пагінації, стан повноти, пропущені поля/картки та розподіл фільтрів. Наступну сторінку планує worker.

Один виклик не обходить усі сторінки, не відкриває кожне оголошення й не починає прихований нескінченний цикл.

## Вхідний контракт

Типізований контракт реалізовано в `vpars_parser/models.py`, HTTP — `POST /v1/catalog/parse`. OpenAPI доступний на `/docs`. Гроші в JSON передаються десятковими рядками; вхідні числові суми відхиляються для захисту від float-похибок. Додатковий явний `search_text` передається gateway; списки `filters.models` та `filters.keywords` зберігаються для перевірки worker без звуження OR.

| Поле | Правило |
|---|---|
| request_id | Кореляція виклику; не є Telegram ID |
| source_id | Спочатку тільки vinted |
| region_id | Один регіон на виклик; GB нормалізується в UK |
| filters | Моделі, розміри, стани, кольори, бренди, категорія, ключові слова, цінові межі |
| page | Позитивне ціле число, типово 1 для Vinted; адаптери майбутніх сайтів можуть мати власний курсор |
| timeout_seconds | Бюджет запиту до браузера, узгоджений із загальним строком HTTP/gRPC |

Множинні параметри задаються списками. Порожнє/відсутнє значення означає відсутність обмеження. Цінова межа містить Decimal-суму й явний код валюти; мінімум не перевищує максимум. Валюту не вгадувати й не прирівнювати UAH-відображення до валюти фільтра. Правило введення валюти в боті ще не визначене; це не заважає зробити явний контракт parser.

## Семантика фільтрів

Ввід із бота англомовний, але назви й значення на сторінках можуть бути іншими мовами. Мапінги зберігають і вихідні, і нормалізовані значення та враховують регіон/категорію. Непідтверджені ID довідників не вигадуються.

Між параметрами діє AND, між альтернативами одного параметра — OR. Наприклад: бренд Nike AND (M OR L) AND (Black OR Grey). В одній картці можуть бути кілька моделей; це не кілька тарифних місць і зараз жодних тарифних місць немає.

Кожний активний фільтр отримує явний статус:

- applied_filters — застосований у запиті джерела без втрати допустимих варіантів;
- residual_filters — перевірятиметься worker за доступними полями лота;
- UnsupportedFilter — неможливо надійно застосувати в джерелі чи перевірити за результатом.

Якщо gateway не приймає size, але HTML надійно дає розмір, цей фільтр може бути residual. Якщо стан у доступному форматі взагалі не отримується, не оголошувати фільтр стану підтримуваним. Окремий лот із відсутнім значенням має unknown/null; активний фільтр за цим полем не вважається підтвердженим збігом у worker.

Один search_text не гарантує OR для кількох моделей. Не можна вибрати тільки першу альтернативу або склеїти їх у вужчий запит. Використати перевірений ширший запит із residual-перевіркою або повернути явну непідтримуваність цієї комбінації. Якщо знадобиться розгалуження на кілька каталогів, погодити його контракт із worker, який керує пагінацією й бюджетом запитів.

Остаточний збіг за всіма фільтрами перевіряє worker. Автоматичний переклад довільних моделей/ключових слів не є вимогою. Стан, розмір і бренд не витягуються здогадкою з назви.

## Нормалізований лот

| Поле | Значення |
|---|---|
| source_id, region_id | Джерело й каталог фактичної відповіді |
| source_namespace, source_item_id | Область унікальності та рядковий ID лота |
| title | Назва з очищеним зайвим пробілом, без вигаданих атрибутів |
| price.amount, price.currency | Decimal-сума товару та валюта джерела; у JSON сума передається десятковим рядком |
| item_url | Перевірене посилання на оголошення потрібного джерела |
| photo_urls | URL фото з відповіді; порожній список допустимий, зображення не завантажуються |
| brand, condition, size, colors, category | Вихідні й нормалізовані значення, коли вони доступні |
| availability | Значення джерела або unknown |
| fetched_at | Час отримання в UTC |
| source_attributes | Необов'язкові додаткові поля адаптера без вимоги їх наявності на інших сайтах |

Не плутати ціну товару із сумою доставки, комісій або підсумком покупця. Не використовувати float для грошей. Відсутній розмір, стан або фото не вигадувати.

Для придатної картки потрібні ідентичність, назва, однозначні ціна/валюта та посилання. Пошкоджений запис пропускається з причиною й partial для сторінки; відсутність необов'язкового атрибута позначається null/unknown та не обов'язково означає пошкоджену сторінку. Якщо всі картки відкинуто через зміну структури, це помилка формату, а не підтверджений порожній каталог.

Ідентичність — (source_id, source_namespace, source_item_id). Поки глобальність ID між регіонами не доведена, namespace включає регіон. Дедуплікація parser обмежена однією відповіддю; між сторінками, регіонами й користувачами її веде worker за [SOURCES.md](../../../docs/SOURCES.md).

## Результат, пагінація й помилки

Успішна відповідь містить items, source_id/region_id, request_id, pagination, completeness, warnings, applied_filters і residual_filters. Pagination передає requested_page, next_page/cursor за наявності та has_more=true/false/unknown. Completeness=complete означає повноту розбору отриманої сторінки, а не зібраний увесь каталог. Partial містить причини пропусків.

Не вважати наступну сторінку наявною тільки через page+1 і не оголошувати кінець каталогу за відсутністю доказів. Невідомий стан повідомляється worker; контрольні точки та рішення про додаткову перевірку належать йому. Поточний gateway не задає сортування: не обіцяти, що перша сторінка завжди містить найновіші лоти.

| Випадок | Поведінка parser |
|---|---|
| INVALID_ARGUMENT | Явна помилка запиту, без повторного запуску того самого виклику |
| RESOURCE_EXHAUSTED | Передати проблему місткості/розміру; не створювати цикл негайних повторів |
| DEADLINE_EXCEEDED / TIMEOUT | Структурований таймаут зі збереженням категорії причини |
| BLOCKED / RATE_LIMITED | Помилка доступу/обмеження частоти, а не порожній список |
| UNEXPECTED_REDIRECT / UNEXPECTED_CONTENT | Відхилення від очікуваного каталогу; не маскувати HTML сторінки захисту під результат |
| UPSTREAM_ERROR / SERVICE_ERROR або транспортний збій | Явна помилка залежності |
| PAGE_LOADED без потрібного HTML | Помилка контракту; item_samples не замінює повний каталог |
| Пошкоджений формат карток | Partial або SchemaChanged залежно від обсягу пошкодження |

Помилки передають request_id, стабільний код, безпечний опис і джерельний статус. Worker вирішує, коли повторити перевірку; parser не повторює невідомий результат самостійно.

Важлива поточна прогалина: classify у gateway вважає PAGE_LOADED лише каталог із посиланнями на товари. Справді порожня сторінка зараз потрапляє в UNEXPECTED_CONTENT, і HTML через gRPC для неї не передається. Parser не може достовірно повернути complete + items=[] або підтверджений кінець каталогу за такою відповіддю. Для цього потрібне окреме підтверджене розширення класифікації/контракту gateway; до нього повертати явну непідтвердженість, не обходячи захист від сторінок блокування.

## Швидкодія та перевірка реалізації

Реалізація використовує асинхронний gRPC-клієнт із довгоживучим каналом і закриттям на завершенні, gzip, ліміт 32 МіБ та строк timeout_seconds + 15 с. Синхронний VintedClient не викликається. HTTP-бюджет включає окремий контрольний RPC і обробку HTML; параметри наведені в README.

Паралельність має бути обмежена. Скасування RPC не означає, що синхронний Byparr-виклик уже припинився; не звільняти уявну місткість повторним штурмом gateway. Ціль 60 запитів/хв не означає 60 успішних відповідей і не є виміряною характеристикою parser.

Вимірювати окремо час gateway, розбору й нормалізації, кількість валідних/пропущених карток, обсяг відповіді та категорії помилок. Не записувати сирий HTML чи секрети в звичайні журнали. Кеш довідників прив'язати до джерела, регіону, категорії й версії; не кешувати живий каталог надовго без узгодженої допустимої давності.

Перевірки реалізації: справжні знеособлені зразки HTML доступних регіонів, різні ціни/валюти, відсутні атрибути, дубль картки, пошкоджений формат, блокування, невідоме продовження, усі відомі outcome, відсутній HTML і OR-фільтри. Заглушка gateway потрібна для відтворюваних контрактних тестів, але не доводить роботу на живому Vinted. Підтримка порожнього каталогу перевіряється окремо з урахуванням прогалини вище.
