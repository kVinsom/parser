# Архітектура parser

[README](../README.md) · [Контракт](PARSING.md) · [Патерни проєкту](../../../docs/PATTERNS.md)

Стан 2026-09-22: реалізований stateless-сервіс. Worker звертається HTTP до
FastAPI, parser — через асинхронний gRPC до наявного VintedAccess. Один виклик
означає одну сторінку. Повторів, планувальника, бази даних, Redis, підписок і
персональної історії тут немає.

```text
worker → api.py → ParserService → AdapterRegistry → VintedAdapter.build_query
                      ↓
               GatewayClient port → GrpcGatewayClient → existing VintedAccess
                      ↓ HTML only after PAGE_LOADED
          VintedAdapter.parse_page → normalize_item → page-local merge
                      ↓
           ParseResult + pagination + filter checks + completeness
```

| Модуль `vpars_parser/` | Відповідальність |
|---|---|
| `models.py` | Pydantic 2: запит, суми Decimal, атрибути raw/normalized, лот, результат, помилка, capabilities |
| `ports.py` | Protocol GatewayClient/SourceAdapter; типізовані GatewayQuery/Page, QueryPlan/ParsedPage |
| `settings.py` | Валідовані бюджети, адреса gateway, розміри та паралельність |
| `gateway.py` | `grpc.aio`, один канал, timeout+15, gzip, 32 МіБ, безпечне зіставлення статусів |
| `sources/vinted.py` | Фактичні DOM-селектори, ціни, локалізовані підписи, нормалізація, фільтри, перевірка URL/регіону, пагінація |
| `service.py` | Реєстр адаптерів, послідовність кроків, загальний бюджет, місткість, partial, дедуплікація в межах сторінки |
| `api.py` | HTTP-контракт, 64 КіБ для тіла запиту, request_id, health, lifespan, безпечні помилки |
| `errors.py` | ParserError зі стабільним кодом, HTTP-статусом та категорією джерела |

`SourceAdapter` має `capabilities`, `build_query`, `parse_page`, `normalize_item`,
а також явну регіональну валідацію. Наступний маркетплейс додається окремим
адаптером у реєстр; його селектори не змінюють DTO лота. Поточний транспорт
підтримує лише VintedAccess: новий сайт також потребуватиме свого реалізованого
порту доступу, а не підміни URL у запиті Vinted.

Відомі фільтри діляться на застосовані в gateway, перевірки worker та
непідтримувані. Кілька моделей залишаються OR-альтернативами в residual-перевірці;
пошук не звужується першою моделлю. Пропущені/невідомі атрибути не вигадуються.
Ідентичність `(source_id, source_namespace, source_item_id)` включає регіон,
оскільки глобальність Vinted ID між каталогами не доведена.

Місткість обмежується активними asyncio tasks на весь цикл, включно з DOM-роботою
в потоці. Скасування очікування з боку клієнта не знімає облік активної роботи.
Додаткові запити відхиляються одразу без прихованої черги. Deadline браузера та
gRPC узгоджені з фактичним gateway; немає циклу автоматичних повторів.

Розбір і нормалізація запускаються поза event loop. Загальний HTTP-бюджет не
означає примусове завершення C-парсера в потоці: слот утримується до фактичного
завершення. Для жорсткого CPU-deadline потрібна майбутня процесна ізоляція.
Статистики часу, кількості карток/лотів, пропусків і байтів передаються worker.

Довідників gateway не надає, тому кеш довідників зараз не створено. Живі каталоги
не кешуються; протокол генерується з наявної схеми gateway, не дублюється.
Необхідні майбутні зміни — [GATEWAY_GAPS.md](GATEWAY_GAPS.md).

HTML розбирається Lexbor із selectolax; селектори підтверджені реальними
сторінками. Заміна попереднього Modest зменшила локальний час на 14,67% у
400 парних порівняннях зі збереженням усіх результатів. Це не відсоток
прискорення мережевого шляху: [методика та виміри](LATENCY.md).

Перевірки охоплюють реальні знеособлені HTML, синтетичні граничні випадки,
заглушку порту gateway, справжній локальний gRPC і окремий live-smoke через
готовий gateway. Результати — [VALIDATION.md](VALIDATION.md).
