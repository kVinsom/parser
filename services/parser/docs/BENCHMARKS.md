# Автотести й бенчмарки parser

## Одна команда перевірки

Із `services/parser`, після встановлення `requirements-dev.txt`:

```powershell
.\run.ps1 --qa
```

За замовчуванням це **offline**: генерація protobuf з чинної схеми gateway,
Ruff lint, перевірка форматування, всі pytest-тести та локальний бенчмарк.
Для будь-якого іншого поточного каталогу можна викликати `run.ps1` повним шляхом.
Без PowerShell: `python tools/qa.py` або `python tools/benchmark.py` із каталогу сервісу.

Невдалий крок зупиняє наступні. Пропущені тести, порожній або пошкоджений JUnit
не вважаються успішною перевіркою. QA має 180-секундний бюджет на кожний локальний
етап. Живі запити не виконуються, поки тести й перевірки коду не пройшли.

```powershell
# Локальні тести й бенчмарк, потім 3 × 4 живих запити:
.\run.ps1 --qa --mode both --rounds 3 --pause 0.5

# Бенчмарк без повторення тестів, тільки збережені повні HTML:
.\run.ps1 --benchmark --capture-directory ../access-gateway/bypass/.artifacts/grpc-20260915T213415Z-28557d9c

# Лише живий HTTP-шлях; Docker і gateway мають бути запущені:
.\run.ps1 --benchmark --mode live --regions UK FR IT DE --rounds 3

# Приклад явних порогів; це налаштування перевірки, не обіцяна продуктивність:
.\run.ps1 --qa --mode both --max-local-p95-ms 100 --max-live-p95-ms 10000
```

`--test` запускає тільки pytest; `--serve` запускає API. Порожній виклик `run.ps1`
еквівалентний `--qa`. Скрипти самі не встановлюють залежності, не запускають Docker
і не додають завдань за розкладом.

## Що вимірюється

**Offline:** один цикл parse → normalize/merge → JSON серіалізація списку лотів.
Додатково вимірюються `parse_ms`, `normalization_ms`, `serialization_ms`.
Читання файлів, gzip-розпакування, UTF-8 декодування, підготовка запиту й прогрів
виконуються до вимірюваного циклу. Мережевих запитів немає.

За замовчуванням використовуються знеособлені реальні fixtures із 8–10 картками;
вони придатні для швидкої регресійної перевірки, але не представляють час обробки
повної сторінки. `--capture-directory` вибирає **повні** `{REGION}.html.gz`.
Файли не змінюються; у звіті є SHA-256 розпакованого HTML, розмір і тип зразка.
Читання обмежене 32 МіБ після розпакування. Прогрів не входить до статистики.

**Live:** HTTP-клієнт → тимчасовий Uvicorn → parser → існуючий gRPC gateway →
Vinted → нормалізована HTTP-відповідь. Клієнт і gRPC-канал повторно використовуються.
Вимірюваний HTTP-час включає декодування й валідацію відповіді клієнтом;
серверні `access_ms`, `parse_ms`, `normalization_ms`, `parser_total_ms` зберігаються
окремо. Вкладені етапи не треба додавати до повного HTTP-часу.

Перший каталог включено в статистику; прихованих прогрівних запитів до Vinted
немає. Health/readiness перевіряють процес і ListRegions до вимірювання каталогів.
Один вимір — page=1 без пошукового тексту; обхід наступних сторінок не запускається.
Наступні регіони та кола виконуються послідовно з паузами. Тимчасовий HTTP-процес
після завершення закривається; чинні gateway/Byparr не зупиняються й не змінюються.

Дані після блокування/429, SchemaChanged, UnexpectedContent або недоступного
регіону припиняють подальші кола для цього регіону. Partial також припиняє його
подальші кола. Таймаут, перевантаження, транспортна або інша невизначена помилка
зупиняють весь live-бенчмарк. Автоповторів немає. Пропущені через зупинку запити
залишаються `not_attempted`, а весь запуск — неповним і неуспішним.

## Статистика й критерії

- mean, median, min/max і p95 розраховуються **лише для complete-відповідей**.
  Partial, помилки та відсутні вимірювання не стають нулями чи успіхами.
- p95 — найближчий ранг `ceil(0.95 × N)`. Для трьох живих вимірів регіону це максимум;
  така мала вибірка не доводить стабільність майбутнього p95.
- Частка успіху = complete / усі **заплановані**, а не тільки виконані запити.
  Окремо є `partial`, `failed`, `not_attempted` і категорії помилок.
- Пороги p95 перевіряються **для кожного регіону**, щоб швидкий регіон не приховував
  повільний. Типово часових порогів немає; мінімум успіху — 100%.
- Навіть зі зниженим `--min-success-rate` незавершений запуск або відсутність
  успішних вимірів не проходить. У `both` провал локального бенчмарку блокує live.
- `observed_complete_pages_per_minute` — фактична швидкість за виміряний період:
  включає паузи, помилки й запис проміжних звітів. Часи окремих запитів не включають
  запис звіту. Показник не є граничною пропускною здатністю й не доводить 60 запитів/хв.

## Параметри

Параметри спільні для `--qa` та `--benchmark`:

| Параметр | Типово | Межі / значення |
|---|---|---|
| `--mode` | offline | offline, live, both |
| `--regions` | UK FR IT DE | GB → UK; дублікати прибираються; PL заборонений |
| `--iterations` | 50 | 1–1000 локальних вимірів на регіон |
| `--warmup` | 3 | 0–20 локальних прогрівних циклів |
| `--capture-directory` | не задано | Папка повних `.html.gz`; інакше знеособлені fixtures |
| `--rounds` | 3 | 1–5; не більше 20 живих запитів |
| `--pause` | 0.5 | 0–30 с між живими запитами |
| `--browser-timeout` | 60 | 1–300 с; HTTP-бюджет враховує всі резерви parser |
| `--min-success-rate` | 100 | 0–100%, із вимогою завершеності запуску |
| `--max-local-p95-ms` | не задано | Додатний локальний поріг, тільки offline/both |
| `--max-live-p95-ms` | не задано | Додатний HTTP-поріг, тільки live/both |

NaN, нескінченність і значення поза межами відхиляються до роботи.
Адреса gateway — з `PARSER_GATEWAY_TARGET`, як у звичайного parser; вона не
підміняється прямою адресою Vinted. Налаштування gateway не переписуються.

Коди завершення: **0** — виконано критерії; **1** — помилка перевірки/середовища,
невиконаний критерій або неповний запуск; **2** — некоректні CLI-параметри;
**130** — переривання. Таким самим кодом завершується `run.ps1`.

## Звіти

Кожний запуск має нову папку `.artifacts/qa-ДАТА-ID/` або `benchmark-ДАТА-ID/`.
`report.json` містить налаштування, версії Python/бібліотек, входи, кожний вимір,
агрегати по регіонах і причини непроходження критеріїв. `report.md` — короткий звіт.
Звіти оновлюються атомарною заміною; старі запуски не перезаписуються.

QA додатково зберігає `tests.xml` (JUnit), `tests.log`, `contracts.log`, `lint.log`,
`format.log`, а бенчмарк — у вкладеній папці `benchmark/`. Проміжний стан — running;
перерваний або аварійний запуск не отримує passed. Сирий HTML, лоти та внутрішні
тексти винятків у benchmark-звіти не потрапляють. Повний лог pytest призначений
для локальної діагностики тестів.
