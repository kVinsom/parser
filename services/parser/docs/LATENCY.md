# Оптимізація затримки — 2026-09-22

У `VintedAdapter` замінено Modest HTMLParser на LexborHTMLParser з тієї самої
зафіксованої залежності `selectolax==0.4.12`. Окремі атрибути читаються через
`node.attrs`, без побудови повного словника `node.attributes` для кожного читання.
Перевірені селектори, поля, валідація, помилки та пагінація збережені.
Сирий HTML не обрізається; scripts, style та comments обробляє HTML-парсер.
Gateway/Byparr, їхній контракт і налаштування обходу не змінювалися.

## Виміряне зменшення

Порівняння проведено на Windows/Python 3.12.14. Формула:
`(час_до − час_після) / час_до × 100%`. Від’ємне значення означає погіршення.

| Вимір | До | Після | Зменшення |
|---|---:|---:|---:|
| Парний локальний тест, середній час сторінки | 17,797 мс | 15,186 мс | **14,67%** |
| Окремі послідовні offline-запуски, середній час | 17,457 мс | 15,082 мс | 13,61% |
| Живий HTTP-запит, середній час | 2998,488 мс | 2948,025 мс | **1,68% спостережувано** |
| Живий HTTP-запит, p95 | 3589,511 мс | 3302,724 мс | 7,99% спостережувано |

**14,67% — виграш локального parse → normalize → JSON, а не повного запиту до
Vinted.** Перевірено 400 пар: по 100 на UK, FR, IT, DE, 96 лотів у кожній сторінці.
Порядок старого/нового адаптерів чергується AB/BA. По 5 прогрівних пар на регіон
виключено. Ті самі повні HTML із gateway від 2026-09-15 завантажено до таймерів;
SHA-256 входів і вихідного коду збережено. Читання, gzip, декодування та перевірка
рівності не входять у локальний час. Порівняно всі поля лотів, порядок, пагінацію,
попередження, лічильники й повноту; час `fetched_at` фіксований для обох версій.
Усі 400 пар мають однакові результати. Partial або розбіжність зупиняє порівняння.

## Що показав живий Vinted

До змін: 12/12 complete; після: 12/12 complete. Обидва запуски — по три запити
на регіон, послідовно, пауза 0,5 с, page=1, без пошукового тексту й повторів.
HTML надходив через чинний gRPC gateway з `include_html=true`.

| Регіон | Середній HTTP-час до, мс | Після, мс | Спостережувана зміна |
|---|---:|---:|---:|
| UK | 3088,719 | 2700,334 | −12,57% часу |
| FR | 2944,868 | 3036,372 | +3,11% часу |
| IT | 2993,904 | 3120,469 | +4,23% часу |
| DE | 2966,459 | 2934,924 | −1,06% часу |

Це мала послідовна вибірка з мінливим каталогом і мережевим часом; p95 для всіх
12 запитів дорівнює максимуму. Вона **не доводить причинного зменшення HTTP-часу
на 1,68%**: зміна в різних регіонах навіть має різний знак. Контейнер браузера
був щойно відновлений перед базовим запуском; перший каталог включено в замір.

Середній `access_ms` змінився з 2972,009 до 2924,072 мс. Після оптимізації це
близько **99,2% HTTP-часу**. DOM-розбір живих сторінок змінився з 14,617 до
12,216 мс; нормалізація — з 2,887 до 2,861 мс. Очікуваний внесок локально
заощаджених 2,61 мс у запит тривалістю 3 с — лише близько 0,09% за інших рівних
умов; це оцінка, не окреме вимірювання повного шляху.

Подальше помітне зниження повної затримки потребує окремого дослідження
browser/gateway. Дані каталогу не кешуються, перевірки не пропускаються,
PL залишається вимкненим. Прогалини gateway щодо порожнього каталогу,
фільтрів і кінця пагінації залишаються в [GATEWAY_GAPS.md](GATEWAY_GAPS.md).

## Відтворення

Із `services/parser`, з установленими dev-залежностями:

```powershell
.\run.ps1 --qa

# Тільки локальне порівняння з реально збереженим попереднім адаптером:
.\.venv\Scripts\python.exe tools/compare_latency.py --baseline-adapter .artifacts/latency-baseline-20260922/vinted.py --capture-directory ../access-gateway/bypass/.artifacts/grpc-20260915T213415Z-28557d9c --iterations 100 --warmup 5

# Окремо повні HTML та 12 живих HTTP-запитів; gateway має працювати:
.\run.ps1 --benchmark --mode both --capture-directory ../access-gateway/bypass/.artifacts/grpc-20260915T213415Z-28557d9c --iterations 100 --rounds 3 --pause 0.5
```

`--baseline-adapter` завантажує Python-код: використовувати власну довірену
локальну копію `sources/vinted.py`, збережену **до** змін. Копія від цього
запуску й повні HTML є локальними артефактами, не частиною дистрибуції.
Без `--capture-directory` порівнюються скорочені реальні fixtures.
Спільний `normalize_page` не змінювався: інструмент ізолює зміну адаптера;
для змін інших шарів потрібне порівняння повних версій сервісу.

Звіти містять хеші, лічильники й часи, без HTML або тексту оголошень.
Вихід 0 означає завершене порівняння однакових результатів, а не гарантоване
прискорення. Регресії зберігаються з від’ємним відсотком, відсутні дані — null.
