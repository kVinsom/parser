# Vinted: доступ, перевірки та бенчмарки

Модуль читає публічні каталоги Vinted через локальний контейнер Byparr 3.0.4.
Окремий контейнер `gateway` надає [доступ через gRPC](GRPC.md) на `127.0.0.1:50051`.
Доступні чотири регіони:

| Код | Домен |
|---|---|
| UK | `vinted.co.uk` |
| FR | `vinted.fr` |
| IT | `vinted.it` |
| DE | `vinted.de` |

`GB` — синонім `UK`; `all` вибирає ці чотири регіони. Типовий регіон — FR.
Польський регіон вилучено: код `PL` відхиляється до звернення до браузера.
Код регіону визначає домен каталогу, а не країну кожного продавця.

## Запуск

Потрібні Docker Desktop і Python 3.12+. У поточному середовищі Python та
локальні залежності вже доступні. Окремий сервер і локальний Chromium не потрібні.

Із цієї папки в PowerShell:

```powershell
docker compose up -d --build --wait
.\run.ps1 --grpc --health
.\run.ps1 --regions all
.\run.ps1 --region DE --search-text "nike" --page 2
.\run.ps1 --list-regions
```

Із кореня проєкту використовувати `services\access-gateway\bypass\run.ps1`.
Старий префікс `--vinted` також підтримується. `run.ps1` шукає Python у
`.venv`, встановленому середовищі Codex або PATH; явний шлях задає `VINTED_PYTHON`.

У новому середовищі:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-grpc.txt
docker compose up -d --build --wait
.\run.ps1 --regions all
```

На Linux: `python3 -m venv .venv`, установити `requirements-grpc.txt` у це
середовище, потім `.venv/bin/python vinted.py --regions all`.

## Налаштування і результат

Відредагувати `.env` за прикладом `.env.example` за потреби.
`BYPARR_URL` — адреса готового сервісу, типово `http://127.0.0.1:8191`.
Пріоритет: `--byparr-url`, оточення процесу, `.env`, типове значення.
Параметри `PROXY_SERVER`, `PROXY_USERNAME`, `PROXY_PASSWORD` стосуються
браузера в Docker. Після зміни проксі виконати `docker compose up -d`.
Мова браузера задається в `compose.yaml`; перемикання доменів не змінює проксі.

Byparr очікує завершення завантаження каталогу й повертає оновлений HTML,
щоб парсер бачив усі картки та пагінацію. Швидке повернення деталей товару
потребує підтверджених галереї, опису, продавця й часу публікації.
Неповні сторінки проходять звичайне очікування та перевірки доступу.
Службова перевірка `/health` перевіряє локальну вкладку без зовнішнього сайту.
Це реалізовано в `byparr_runtime.py` для зафіксованої версії 3.0.4;
Compose підключає потрібні файли тільки для читання.
Для порівняння зі стандартним очікуванням встановити `VINTED_FAST_CATALOGS=0`
у `.env` і виконати `docker compose up -d`. Значення 1 повертає швидкий режим.
Після редагування файлів потрібен перезапуск сервісу. Для працюючого монітора
застосовувати з кореня проєкту
`services/telegram-bot/.venv/Scripts/python.exe services/worker/tools/restart_safely.py --reload-gateway`:
він завершує активні звернення й відправлення перед перезапуском та відновлює розклад.

Браузерний процес повторно використовується. Звичайні запити отримують новий
ізольований контекст. З `VINTED_ITEMS_CATALOG=1` пошук нових товарів використовує
окремий анонімний контекст для кожного регіону, зі свіжою вкладкою на запит.
Облікові дані користувачів не підставляються; контексти різних регіонів,
деталей товарів і явних проксі не об'єднуються. Після 50 використань браузер оновлюється,
щойно завершилися активні запити. Після розриву з'єднання наступний запит
запускає новий браузер. Це прибирає повторний запуск процесу для кожного каталогу.
Для контрольного режиму встановити `VINTED_REUSE_BROWSER=0` у `.env` і виконати
`docker compose up -d`. Явні проксі в HTTP-заголовках Byparr використовують
початковий режим окремого браузера на запит. Налаштування проксі та мови збережені.

Локальна помилка першої навігації `loadURI / browsingContext is undefined`
або конфлікт з `about:blank`/`about:newtab` дозволяє одну заміну вкладки.
Несправна вкладка закривається перед створенням нової; контекст, проксі,
cookies й початковий ліміт часу зберігаються, маршрути ресурсів встановлюються
заново. Це не повтор відповіді 403/429, перевірки доступу чи звичайного таймауту.
`verify_browser_recovery.py` перевіряє обидва режими браузера й відновлення
на локальній сторінці в робочому Docker-образі.

Зображення, відео та шрифти типово не завантажуються. Для діагностики
або порівняння використати `--load-media`. HTML і посилання на товари зберігаються.
`--timeout` — 1–300 секунд на запит (типово 60), плюс 10 секунд на відповідь API.

Кожний запуск створює `report.json` та `report.md` у `.artifacts/`.
`--save-html` додатково зберігає сторінки як `UK.html.gz`, `FR.html.gz` тощо.
Gzip зменшує місце на диску без втрати вмісту. Програмний `result.body`
містить звичайний HTML; стискання стосується лише збережених файлів.

```python
from vinted import fetch_catalog

result = fetch_catalog("DE", search_text="nike")
if result.outcome == "page_loaded":
    print(result.item_count, result.item_samples)
    html = result.body
else:
    print(result.outcome, result.reason)
```

Успіх вимагає потрібного регіонального домену й каталогу, заголовка Vinted,
посилань на товари та відсутності виявленої CAPTCHA. Самого HTTP 200 недостатньо.
`item_count` рахує унікальні ID на сторінці; `item_link_count` включає повторні посилання.
Cookies між запитами не переносяться; ключі й облікові дані проксі не записуються у звіт.
HTML може містити тимчасові токени; `.artifacts/` і `.env` ігноруються Git.

Можливі результати: `page_loaded`, `blocked`, `rate_limited`, `unexpected_redirect`,
`unexpected_content`, `upstream_error`, `service_error`, `timeout`.
Порожня видача позначається `unexpected_content`: доступ до товарів не підтверджено.
Коди завершення `vinted.py`: 0 — усі вибрані каталоги доступні; 2 — невдача
або неправильні аргументи; 130 — переривання. Звіт зберігається після кожного регіону.

## Автотести та бенчмарки

Окремий замір затримок через gRPC: `run.ps1 --latency` — три запити на кожен
регіон з передаванням HTML, 30 локальних викликів без Vinted, звіт у
`.artifacts/latency-ДАТА-ID/`. Окремо вимірюються HTTP-виклик Byparr,
обробка відповіді й gRPC. Усередині браузера додатково вимірюється основний
HTTP-запит HTML до Vinted. Запис звіту не входить до таймерів.
Це вимірювання модуля доступу, без затримки черги й доставки Telegram.
Параметри й визначення часу наведено в [GRPC.md](GRPC.md).

```powershell
# Тести, три кола по чотирьох регіонах, 10 вимірювань обробки HTML на регіон
.\run.ps1 --qa

# Без Docker і зовнішніх запитів
.\run.ps1 --qa --offline

# Лише бенчмарк; медіафайли увімкнені для порівняння
.\run.ps1 --qa --benchmark-only --load-media

# Необов'язкова верхня межа p95 успішних запитів
.\run.ps1 --qa --max-p95 20
```

На Linux: `.venv/bin/python qa.py`. Швидкий запуск тестів: `run.ps1 --test`.

| Параметр `--qa` | Типово | Межі / значення |
|---|---|---|
| `--regions` | `all` | UK, FR, IT, DE |
| `--rounds` | 3 | 1–10, щонайбільше 40 запитів |
| `--pause` | 1 с | 0–30 с між запитами |
| `--timeout` | 60 с | 1–300 с плюс 10 с на відповідь API |
| `--parse-iterations` | 10 | 1–100 локальних вимірювань |
| `--min-success-rate` | 100% | Мінімальна частка успішних виконаних запитів |
| `--max-p95` | не задано | Верхня межа p95 успішних запитів, секунди |
| `--load-media` | вимкнено | Увімкнути зображення, відео та шрифти |

Звіти `.artifacts/qa-ДАТА-ID/`: `report.md`, `report.json`, `tests.log`,
`tests.xml` (JUnit), перша успішна сторінка кожного регіону в `.html.gz`.
Перша невдала HTML-відповідь зберігається як `*-failed.html.gz`.

Тести перевіряють маршрутизацію, розпізнавання блокування, помилки сервісу,
стискання сторінок і логіку бенчмарку. Невдалий або пропущений тест зупиняє
повний запуск до зовнішніх запитів. CAPTCHA чи обмеження частоти зупиняють
наступні спроби відповідного регіону, помилка Byparr — весь бенчмарк.
Неповний запуск не отримує успішний підсумок.

Звіт містить середнє, медіану, p95, мінімум і максимум часу, частку успіху,
кількість товарів та спостережувану швидкість. Час запиту включає браузер,
передавання HTML та перевірку вмісту. Швидкість враховує паузи і запис звітів.
Обробка HTML вимірюється окремо, після читання та розпакування файлу, без мережі.
p95 — найближчий ранг `ceil(0.95 × N)`; на трьох запитах це максимум.
Це послідовний бенчмарк, не вимірювання граничного навантаження.

Коди завершення `qa.py`: 0 — перевірки пройдено; 1 — провал тестів або критеріїв;
2 — помилка запуску; 130 — переривання. `--offline` пропускає мережевий етап,
`--benchmark-only` — локальні тести. Команда виконує один завершений запуск.

## Структура

- `vinted.py`, `vinted_regions.py` — доступ і чотири дозволені регіони;
- `browser_pool.py`, `test_browser_pool.py` — повторне використання процесу з ізольованими контекстами;
- `grpc_server.py`, `grpc_client.py`, `grpc_common.py`, `vinted_rpc/` — інтерфейс gRPC;
- `proto/vinted_rpc/access.proto`, `Dockerfile.grpc` — контракт і збірка gateway;
- `latency.py`, `test_latency.py`, `test_grpc.py` — вимірювання затримок і перевірки транспорту;
- `artifacts.py` — стиснуті HTML-знімки;
- `byparr_runtime.py`, `test_byparr_runtime.py` — повернення готових каталогів і карток лотів без зайвого очікування;
- `qa.py`, `test_vinted.py`, `test_qa.py` — перевірки й бенчмарки;
- `compose.yaml`, `requirements.txt`, `run.ps1` — запуск;
- `.deps/` — локальні Python-залежності; `.tmp/` — тимчасові файли.

Leboncoin, його CAPTCHA-адаптери та локальний Chromium видалені.
Поточний модуль читає публічні каталоги; робота 24/7 і надійне проходження
реальних CAPTCHA потребують окремої перевірки.

## Економія трафіку — 08 жовтня 2026 року

`VINTED_STATIC_CACHE=1` вмикає спільний обмежений кеш публічних незмінних
JS/CSS Vinted; каталоги, деталі, API та cookies не кешуються. Кеш зберігається
між ротаціями браузера та, з 09.10.2026, між перезапусками сервісу. Межі RAM: 64 MiB,
512 файлів, 4 MiB на файл, до 24 годин у межах дозволеної свіжості.
`/health` перевіряє локальний браузер без запиту до Google. HTTP-заголовки
`X-Vinted-Static-Cache` та `X-Vinted-Static-Cache-Hits` підтверджують режим.
Для відкату встановити `VINTED_STATIC_CACHE=0` і перестворити Byparr.

Compose монтує `.artifacts/static-cache` у `VINTED_STATIC_CACHE_DIR`.
На диску — до 512 записів / 96 MiB з урахуванням кодування. Кожен запис
публічного JS/CSS записується атомарно; під час відновлення перевіряються ключ,
SHA-256, MIME, дозволи кешування й початковий строк придатності. Перезапуск
не подовжує свіжість. Помилка диска залишає звичайний доступ і кеш у RAM.
Порожній `VINTED_STATIC_CACHE_DIR` у Compose вимикає дискову частину.
`X-Vinted-Static-Cache-Disk` та `X-Vinted-Static-Cache-Restored` показують
стан і кількість відновлених ресурсів.

Одночасні холодні звернення до однакового ресурсу можуть використати один
результат лише після перевірки його придатності до публічного кешу.
Очікування іншого завантаження обмежене 100 мс; далі працює власний запит.
Приватна відповідь, відмова чи збій не передаються іншим контекстам.
`X-Vinted-Static-Cache-Coalesced` показує кількість об'єднаних звернень.

`measure_wire.py` — пасивний лічильник зовнішнього IPv4-трафіку контейнера;
`--benchmark` додає 8 контрольних каталогів без запису в базу й Telegram.
`verify_cached_content.py` перевіряє живі каталоги та деталі звичайним парсером.
`profile_traffic.py` показує ресурси в окремому діагностичному браузері;
його браузерні лічильники не враховують холодні завантаження `route.fetch`.

Прогріта контрольна серія дала −37,29% трафіку та 8/8 успішних каталогів.
Перша серія після запуску мала окремий пік; це не гарантія місячної економії.
[Звіт і обмеження](../../../docs/TRAFFIC_OPTIMIZATION_2026-10-08.md).

`VINTED_SKIP_ANALYTICS=1` додатково вимикає підтверджені Google Tag Manager /
Analytics-скрипти `/gtg/`, точні домени аналітики та явно позначені prefetch
запити. Політика однакова для всіх користувачів і чотирьох регіонів. Звичайні
документи, API товарів, прикладні скрипти, consent-UI та перевірки доступу
залишаються дозволеними. `X-Vinted-Skip-Analytics` показує фактичний режим;
`VINTED_SKIP_ANALYTICS=0` з перезапуском Byparr вимикає цю оптимізацію.

## Компактний каталог і початковий HTML — 9 жовтня 2026 року

`VINTED_DOCUMENT_CATALOG=1` читає повну відповідь головного документа й
перевіряє успішний стан каталогу, точний набір ID, наявність полів карток,
пагінацію та завершення HTML. До результату перевірки супутні ресурси
очікують не більш ніж 2 секунди. Перевірки доступу проходять одразу.
Неповний або невідомий документ продовжує завантажуватися в тій самій
вкладці; другого запиту HTML цей резервний шлях не робить.

`VINTED_COMPACT_CATALOG=1` після першої повної сторінки вивчає публічну
структуру навігації Next.js. Наступні перевірки отримують свіжу компонентну
відповідь лише каталогу. У пам'яті зберігається структура навігації на 30 хвилин,
версія сайту та його параметр `_rsc`; товари й cookies не кешуються.
Контекст, проксі та особисті фільтри залишаються чинними. Зміна версії,
схеми, неповні картки, невідомі ціни або неправильний запит вимикають цей
шлях на 5 хвилин і повертають звичайний HTML. Неповний/порожній окремий
пошук вимикає компактний шлях лише для своєї URL-адреси; збій протоколу
або версії — для регіону. Кеш таких рішень обмежений 256 записами.
Відповіді 401/403/429/5xx
повертаються з початковим статусом і Retry-After без повторного HTML-запиту.

Після підтвердженого читання нової версії HTML регіональна пауза старої
версії скидається; перевірки повноти та паузи окремих пошуків збережені.
Компонентні відповіді запитують `br, gzip`; розпакування виконує транспорт.

`X-Vinted-Catalog-Transport` показує `items`, `compact`, `document` або
`rendered-fallback`; окремі заголовки `X-Vinted-Document-Catalog` та
`X-Vinted-Compact-Catalog` підтверджують увімкнення функцій. Для відкату
встановіть також `VINTED_ITEMS_CATALOG=0` разом з обома прапорцями в `0`
і штатно перезапустіть шлюз.
Кількість товарів, сторінки, контрольні точки й частота пошуку не змінюються.

## Окремий список товарів — 10 жовтня 2026 року

`VINTED_ITEMS_CATALOG=1` вмикає звичайний GET, знайдений у публічному
клієнті Vinted: `https://api.<регіон>/svc-catalogue/items`. На початку
анонімного регіонального сеансу читається повний HTML; це потрібно для
звичайних cookies сайту. Наступні перевірки отримують свіжий JSON без
довідників категорій, зі стисненням Brotli та резервним gzip.
Кількість карток і локаль беруться з перевіреної сторінки, пошук і номер
сторінки — з початкової URL. Невідомі параметри зберігають старий шлях.

Дані проходять ті самі перевірки ID, цін, фото й пагінації перед чинним
парсером. Неповний/невідомий формат використовує резервне читання;
401/403/429/5xx зберігають статус і Retry-After без нового запиту або
заміни сеансу. Товари не кешуються, сеанси не записуються на диск.
Деталі оголошень і доставка фото не змінені. На холодному сеансі або
резервному HTML трафік більший за звичайний запит JSON.

`X-Vinted-Items-Catalog` показує увімкнення; значення `items` у
`X-Vinted-Catalog-Transport` підтверджує фактичне використання.
Вимкнення лише `VINTED_ITEMS_CATALOG` повертає попередні ізольовані
контексти та компактний/HTML транспорт.
Параметр `per_page=24` перевірено, але сайт продовжує віддавати `per_page=96`;
штучного обрізання результатів немає.

`probe_catalog_transport.py` та `probe_rsc_cold.py` — обмежені діагностики.
Запускайте їх через `services/worker/tools/diagnose_traffic.py`, який дренує
поточні звернення, чекає збережених пауз джерела й відновлює розклад у finally.
Контрольні дампи публічних сторінок залишаються локально в артефактах.
[Результати замірів і живих перевірок](../../../docs/CATALOG_TRANSPORT_OPTIMIZATION_2026-10-09.md).

## Історична перевірка — 15 вересня 2026 року

Історичний результат до вилучення польського регіону.

Фінальні **35 тестів пройшли** без пропусків. Оптимізований режим отримав
**15/15 успішних каталогів**, по 96 товарів на сторінці.
Середній час успішних запитів зменшився з **7,873 до 4,827 с** — на **38,69%**
у цьому порівнянні. Контрольний режим мав 14/15 успіхів: одна відповідь DE
містила помилку підключення на стороні Vinted. Її не зараховано як успіх.
Окремо перевірено пошук `nike` на другій сторінці PL після останнього перезапуску.

Видалення та стискання звільнили приблизно **1 ГіБ**; новий HTML-знімок
займає близько 0,9 МБ замість 7 МБ. Збережені звіти містять усі вимірювання.
[Підсумковий звіт](.artifacts/optimization-20260915/report.md).

## Вилучення PL та оптимізація — 22 вересня 2026 року

Активні UK, FR, IT, DE; PL відхиляється у CLI та gRPC. Браузерний процес
повторно використовується з чистим контекстом на кожний запит. У порівнянні
по 12 запитів до й після зміни середній повний час зменшився з **4,55 до 3,41 с**
(**−25,06%**); обидва режими отримали 12/12 каталогів. Пройшли **65 автотестів**
та перевірки ізоляції й відновлення реального браузера в Docker.
[Звіт із вимірюваннями та перевірками](.artifacts/optimization-20260922/report.md).

## Прискорення карток — 27 вересня 2026 року

У режимі `VINTED_FAST_CATALOGS=1` швидке повернення застосовується також до
`/items/{id}`. Потрібні підтверджені регіон/ID/статус сторінки, видима галерея
і JSON-дані саме цього товару з фотографіями, описом та відгуками продавця.
Вбудований JavaScript не виконується для перевірки готовності. Неповні сторінки,
невідомі структури та перевірки доступу проходять звичайний шлях очікування.
Parser додатково перевіряє повноту й узгодженість галереї.

На тих самих трьох публічних лотах UK/DE/IT середній час читання зменшився
з 5,469 до 2,712 с (−50,4%); усі URL фото, опис, дані продавця і дата публікації
збіглися. Це невелика парна вибірка часу читання, а не гарантія наскрізної
затримки Telegram. Пройшли 22 перевірки готовності сторінки й браузерного пулу.
